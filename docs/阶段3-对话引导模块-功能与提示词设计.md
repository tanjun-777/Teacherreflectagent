## 一、模块总览

围绕阶段3「问题-证据-归因-措施对照表」中的**每一条记录**，引导教师开展四阶段反思深化（P1 既有假设外显 → P2 批判性检视 → P3 新认识形成 → P4 宏观行动重构，与界面 `PHASE_LABELS` 一致）。一次聚焦一条记录；各条深化进度独立累积，均计入最终报告。

```
左侧对照表（每行可发起深化） ──点击──▶ 右侧对话面板（AI 引导）
        │                                      │
        ▼                                      ▼
左侧「反思深化结构化框架」卡片 ◀──联动── 阶段结果自动填充
```

## 二、前端功能设计

### 2.1 深化对象选择（左侧对照表最左侧「反思深化」列）

**列内容**（每行，自上而下）：

| 元素 | 说明 |
|---|---|
| 序号 | "第 N 条" |
| 状态徽章 | `未开始`（灰）/ `正在进行`（当前条=蓝底白字；非当前但有进度=琥珀）/ `已完成`（绿） |
| 操作按钮 | 三态文案，与徽章一一对应（见下表） |

**按钮三态与徽章同步表**：

| 条目状态 | 按钮文案 | 徽章 | 悬停提示 | 点击行为 |
|---|---|---|---|---|
| 未开始 | `开展反思深化` | `未开始` | "围绕第 N 条记录开展四阶段反思深化" | 新建该条对话并进入 |
| 正在开展（当前条） | `正在开展反思深化` | `正在进行`（蓝） | "进入第 N 条记录的反思深化对话" | 恢复该条对话与进度 |
| 正在开展（非当前，从其切走的情形） | `正在开展反思深化` | `正在进行`（琥珀） | 同上 | 保存当前条进度后切换回该条继续 |
| 已完成 | `查看反思深化结果` | `已完成` | "查看第 N 条记录的反思深化结果" | 进入该条对话历史，框架显示全部结果 |

**锁定规则**：
- 当前条未完成四阶段时，其他**所有未完成条**（未开始或有历史进度）按钮一律禁用（悬停提示"完成当前记录四个阶段的深化后方可开展其他记录"）；即使绕过禁用触发切换，也会以红字错误拦截（"当前记录的反思深化尚未完成（需完成四个阶段），暂不能开展其他记录；已完成的记录可随时点击查看结果"）
- **已完成条随时可点击**（不受锁定限制，用于查看结果）
- 切换记录时当前条进度自动保存（chat/phase/phaseResults/计数整体写回原行），切回不丢失
- 发送中（chatLoading）所有按钮禁用

**其他**：当前深化行浅蓝背景高亮；单元格内 textarea 编辑与按钮互不影响。

### 2.2 右侧对话面板

| 区域 | 功能 |
|---|---|
| 未选对象时 | 静态提示："请在左侧对照表中点击一条记录的「开展反思深化」按钮，开始该条的四阶段反思深化（一次聚焦一条，完成一条后可继续下一条）" |
| 对话流 | 气泡展示对话历史；选定记录后首条自动生成本条问候语（含该条问题/证据/归因/措施全文 + P1 开放式追问） |
| 阶段指示器 | 1-4 圆点进度条（已完成=绿✓ / 当前=蓝 / 待完成=灰）+ "当前阶段：Phase X — 名称" |
| 当前深化对象栏 | "当前深化对象：第 N 条"+ 完成状态 + 切换提示（未完成时："完成四阶段后方可开展其他记录深化；已完成的记录可随时点击查看结果"） |
| 快捷提问 | 每阶段 3 条模板，点击即发送（见 4.3） |
| 阶段控制 | `← 回退阶段`（Phase≥2 显示）：清除回退阶段及其后旧结果，重新思考；确认完成按钮（本条未完成时显示）：Phase 1-3 文案 `确认Phase X完成 →`，Phase 4 文案 `确认Phase4完成 ✓`（确认后本条深化完成）；均需当前阶段≥1 条实质输入，否则禁用并悬停提示；P4 已确认（本条已完成）后按钮隐藏 |
| 输入区 | textarea（占位提示按阶段语境）+ 发送按钮；支持 Ctrl/Cmd+Enter |
| 错误提示 | 红字显示 chatError（网络/解析失败等） |

### 2.3 左侧「反思深化结构化框架（四阶段）」卡片联动

- 头部显示"当前深化对象：第 N 条"
- 四个阶段块状态：已完成（绿✓ + **结果自动填充**）/ 进行中（蓝）/ 待完成（"完成后自动填充"）
- 点击哪条记录，框架即呈现**该条**的状态与结果（切换时恢复对应条目的 phaseResults）
- 未选对象时：全显示"待完成"，并显示琥珀色引导提示（指向左侧对照表按钮）

### 2.4 多记录状态管理（核心数据结构）

```ts
// 每条记录独立保存（type DeepeningSnapshot）：
{
  active_row: number | null,        // 当前深化对象（行索引；null=尚未选择）
  rows: {
    [idx]: {                        // type RowDeepeningState
      chat: ChatMessage[],          // 该条完整对话历史
      phase: 1|2|3|4,               // 该条当前阶段
      phaseResults: PhaseResults,   // 该条各阶段结果（P1假设/P2审视/P3认识/P4取向）
      phaseInputCounts: Record<number, number>,  // 各阶段实质输入计数
      phaseTurnCounts: Record<number, number>,   // 各阶段对话轮次
    }
  }
}

// 完成状态不单独存布尔字段，统一由结果推导：
// rowFinished(idx) = rows[idx].phaseResults[4]?.status === 'completed'
// 恢复时当前阶段由 derivePhase(已存结果) 推导：P4完成→4；P3完成→4；P2完成→3；P1完成→2；否则→1
```

- **持久化**：上述结构实时写入 `draft_snapshot.deepening`（`session-audit.ts` 串行队列防并发覆盖），刷新/离开页面不丢失；进入页面自动恢复
- **迁移兼容**：旧版单记录数据（`deepening_dialogue` / `deepening_results` / `deepening_phase_inputs` / `deepening_phase_turns`）自动迁移为 `{active_row: null, rows: {0: …}}`——**不默认选中**，进入页面先显示选择列表，由教师自主选择深化对象；选择第 1 条时无缝继续旧对话
- **操作日志**（targetType=`deepening`，优先写入 `session_operation_logs` 表，表不存在时回退 `draft_snapshot.operation_logs`）：
  - `反思深化-选择深化对象` / `反思深化-更换深化对象`（记录序号 + 问题摘录）
  - `反思深化-教师提问` / `反思深化-助手回复`（每轮消息内容截存 2000 字）
  - `反思深化-PhaseN完成`（阶段结果转中文摘要存入 after，1000 字）
  - `提交最终反思报告`（含"对照表共 N 条记录，完成深化 M 条"统计）

### 2.5 阶段推进规则（前端）

| 事件 | 行为 |
|---|---|
| 教师每轮实质输入 | `phaseInputCounts[当前阶段]++`；轮次计数++（确认/回退固定消息**不**计入实质输入，但计入轮次） |
| AI 返回 `phase_result` | 落地到框架卡片 → 自动进入下一阶段 |
| 教师点"确认完成" | 发送确认指令消息（不计输入数；Phase 1-3 发送"确认完成，进入下一阶段"，Phase 4 发送"确认完成，结束本条记录的反思深化"）；**两步机制**——教师尚未总结时 AI 先引导其用自己的话总结（本轮无 phase_result），教师给出总结后 AI 将其整理为该阶段 phase_result |
| 教师点"回退阶段" | **先弹确认层**（列出将被清除的已确认阶段，提示"回退后需重新完成，此操作不可恢复"）→ 确认后清除回退目标阶段及其后所有已确认结果（保留更早阶段结果），输入/轮次计数不清除；随后发送固定回退消息"我想回到上一阶段重新思考"（不计输入数，携带清除后的结果集作为基准） |
| P4 确认完成 | `phaseResults[4].status='completed'` → 徽章变绿、按钮变"查看反思深化结果"、允许切换到其他记录 |

## 三、后端提示词设计（`deepening-coach-chat/route.ts`）

### 3.1 请求消息组装结构

```
messages = [
  { role: 'system', content: 主控Prompt + 专家角色 + 当前阶段Prompt + 动态注入指令 },
  { role: 'user',   content: 焦点记录 + 对照表 + 上下文材料 },   // 首条
  ... 对话历史（截断保护：仅保留最近 40 条消息，normalizedMessages.slice(-40)，并过滤空消息）,
  { role: 'user', content: 教师本轮输入 }
]
```

> 注：选定记录后的首条问候语由**前端本地生成**（`buildRowGreeting`，非 AI 请求产物），含该条问题/证据/归因/措施全文 + P1 开放式追问，作为对话历史的首条 assistant 消息随 messages 送入后端。

- **专家角色**：每次请求注入——学科、学段、教材版本（来自教师 profile），并要求"不与当前任务冲突时结合学科特点提问"
- **焦点记录**：选定记录四字段（问题/证据/归因/措施）以突出格式注入，标注为"唯一焦点"；对照表其余条目仅作背景
- **上下文材料**：教学设计、自评、同伴评价、课堂观察记录、学生表现、学习结果、外部反馈（各自截断保护，超长截断）

### 3.2 主控 System Prompt 结构（共 13 节，状态转移矩阵 4 张计 1 节）

**① 角色定位**：教学反思深化引导助手——围绕教师选定的一条记录，通过对话引导四阶段反思深化；不代替教师思考，只提供支架。

**② 设计原则（六条，最高优先级）**：
1. **以已有反思为起点**：基于对照表记录内容深化，不虚构问题/证据
2. **一次聚焦一条记录**：只讨论焦点记录
3. **审视隐含假设而非优化措施**：严禁输出改进措施、操作清单（属阶段2/其他模块职责）
4. **教师是认识主体**：AI 可提候选解释，但必须请教师确认/修改/否定
5. **不强制认知转变**：允许"修正/确认/重界定/存疑"四种结果，如实接纳教师的最终认识
6. **过程可追溯**：总结必须引用教师实际表述，不替教师生成认识

**③ 支架运用四原则**（源码独立一节）：状态适配（依据对照表与本阶段实际表述选择支持内容）/ 最小必要支持（优先 S6 提问、S2 提示、S5 示范，不直接给结论）/ 动态调节（依据每轮回应调整支持内容与强度）/ 逐步自主（随教师反思能力提高减少直接提示）

**④ 四阶段任务定义**（见 3.3）

**⑤ 六类支架**：S1 反馈（提供与教师当前判断相关的信息——回应、确认、镜像表达，及相关课堂事实/证据/外部观点）/ S2 提示 / S3 指导 / S4 解释 / S5 示范 / S6 提问。主控与四阶段 Prompt 统一使用 S1-S6 编号；"六个支架在每个阶段均可用，区别仅在适用时机"为总则

**⑥ 五类教师回应**（内部识别标注）：A 陈述观点 / B 补充信息 / C 检验假设 / D 修正观点 / E 整合认识

**⑦ 支架动态适配规则**（本次修改强化）：

> 支架依据教师每轮回应动态适配，但适配的宗旨是引导教师完成本阶段任务。每个阶段有明确的产出目标：P1 假设外显、P2 全部假设被审视、P3 形成明确的新认识、P4 形成至少一条宏观行动取向。每轮执行以下步骤：
> 1. 对照本阶段产出目标，判断教师本轮回应的实质进展
> 2. 识别教师回应类型（A-E），并分析其具体内容与思考深度
> 3. 确定当前状态（初始/探索/深化/确认准备）
> 4. 综合阶段目标、回应实质与当前状态，动态选择本轮最合适的一个支架（S1-S6）
> 5. 生成该支架的具体内容——下方矩阵与各阶段支架策略仅为参考起点，当教师回应实质表明其他支架更合适时，以实质判断为准
>
> 适配底线：
> - 教师回应偏离阶段任务或发散时，不跟随发散，选用 S2（提示）或 S3（指导）将对话拉回任务主线
> - 阶段目标基本达成时，引导教师总结本阶段成果并请求其确认，把控推进节奏，不无限发散

**⑧ 四个阶段状态转移矩阵**（回应类型 A-E × 状态 初始/探索/深化/确认准备 → 建议支架；每格附简短策略说明；整体标注"仅为参考起点，以实质判断为准"）

**⑨ 通用转移规则**：
- 连续 2 轮 A（陈述）→ 强制升级支架至 S4（解释）或 S5（示范），打破浅层循环
- 出现 D（修正）或 E（整合）回应 → 下轮优先 S1（反馈），给予确认性回应并推进
- 同一支架连续使用 ≥3 轮 → 强制切换支架类型
- 阶段轮次 ≥8 轮且未确认 → 触发效率提醒，引导教师总结并请求确认

**⑩ 确认门控**（教师总结两步机制）：
- 每阶段结束前，必须引导教师用自己的话总结本阶段成果，再请求教师确认——**总结由教师完成，AI 不替教师总结阶段成果**
- 教师总结若有明显遗漏，可用 S6（提问）请教师补充完善，而非由 AI 补全
- 教师确认后，将其总结整理为结构化结果（<phase_result>）并进入下一阶段
- 确认信号词："确认/对/是的/没问题/可以/OK/好的/同意/就这样"；否认信号词："不对/不是/还要/继续/等一下/差一点/我再想想"
- 教师否认 → 继续当前阶段；教师要求"回到上一阶段" → 允许并重新引导

**⑪ 轮次控制**：每阶段正常 3-6 轮；软上限 8 轮（前端计数，达到后注入提醒）；实质达标可提前推动确认

**⑫ 输出格式硬规则**：

> **每次回复仅使用一个支架**（S1/S2/S3/S4/S5/S6 之一），不得在同一轮组合多个支架。
> 回复 ≤200 字；一次聚焦一个点，不一次抛出多个问题；不替教师完成阶段总结。

**⑬ 阶段完成结构化输出 `phase_result`**：

仅在**教师明确确认**该阶段完成时输出（确认指令通道或确认信号词），四个阶段结构各异（`route.ts:180-206`）：

```
Phase 1：<phase_result>{"phase":1,"assumptions":[{"original_clue":"原始线索","explicated":"外显表述"}]}</phase_result>
Phase 2：<phase_result>{"phase":2,"examinations":[{"assumption":"被检视的假设","method":"检视方式","conclusion":"检视结论"}]}</phase_result>
Phase 3：<phase_result>{"phase":3,"new_understandings":[{"based_on":"基于何种检视","statement":"新认识表述"}]}</phase_result>
Phase 4：<phase_result>{"phase":4,"orientations":[{"linked_understanding":"关联的新认识或审视结论","principle":"今后教学的基本原则或判断标准","orientation":"实践取向"}]}</phase_result>
```

约束（提示词原文）：
- `<phase_result>` 标签仅在教师确认阶段完成时输出，常规对话轮次不输出
- 所有条目内容必须来自教师的实际表述（**尤其是教师本人的阶段总结**），不得虚构；若教师保留了疑问或确认了原有判断，应如实写入对应字段

历史兼容：Phase 4 旧结构 `actions`（情境/时间/方式/预期效果四字段）在后端类型（`PhaseResult.actions`）、上下文回注（`buildPhaseContext`）与前端渲染（框架卡片/报告摘要）中均保留兼容，旧会话数据可正常展示与续传。

### 3.3 四个阶段 Prompt（当前阶段动态注入，四部分结构）

源码位置：`route.ts:208-356`（`PHASE_PROMPTS` 常量）。每个阶段 Prompt = **阶段提示词（核心遵循，含阶段功能定位段）** + **输入（自动注入，P1 无）** + **支架策略（动态适配，两层：支架时机总说明 + 常见情形参考）** + **完成标准**，P4 另附**表述模板**。以下为**完整原文**：

#### Phase 1 - 既有假设外显

```text
## 当前阶段：Phase 1 - 既有假设外显

### 阶段提示词（核心遵循）

你是一名支持教师开展前提反思的对话助手。
请围绕教师选定的完整初步反思记录，引导教师外显其既有判断背后的隐含假设。
首先理解教师对问题、证据、归因和措施的整体判断逻辑，再通过开放式追问，帮助教师表达这些判断所依赖的默认前提、教学观念或判断标准。
不要直接宣布教师的隐含假设是什么。可以提出候选解释，但必须邀请教师确认、修改或否定。
不要直接给出教学改进措施，也不要提前进入批判性审视。重点是帮助教师说清楚自己原先如何理解教学现象，以及这种理解建立在什么认识基础上。
本阶段支架的核心功能是帮助教师将已有但尚未充分外显的判断、认识及其依据明确化——支架将已有认识转化为可进一步检视的外显表征，而非替教师形成新认识。

### 支架策略（动态适配）

本阶段六个支架（S1-S6）均可用，区别仅在适用时机：
- S6（提问）：本阶段主要支架。围绕教师整体判断逻辑开放式追问，帮助其外显隐含假设及其依据
- S2（提示）：教师难以独立表达时，指向盲点、暗示思考方向（如以候选解释提示隐含假设，候选必须请教师确认/修改/否定）
- S5（示范）：给出假设表述的参照示例，帮助教师精确化表达
- S1（反馈）：镜像、确认教师的表达，或提供与其当前判断相关的课堂事实供其对照
- S3（指导）/S4（解释）：仅在教师长期停滞、追问与提示均无效时最低限度使用

以下为常见情形的参考方向，非固定映射；须依据教师回应的实质内容与当前状态，动态选择本轮最合适的一个支架：
- 首轮：S6（提问）——围绕选定记录的整体判断逻辑开放式追问："你当时是怎么理解这次教学现象的？这样的判断建立在什么前提上？"
- 教师 A 类回应 → 视其内容 S6 追问具体情境，或 S2 以候选解释提示隐含假设（候选必须请教师确认/修改/否定）
- 教师 B/C 类回应 → 视其表述完整度 S5 帮助精确化
- 教师 D/E 类回应 → S1 确认，并引导教师总结
- 假设由教师确认且表述清晰时 → 进入确认准备

### 完成标准

- 至少 1 条假设由教师本人确认表述（鼓励挖掘多条）
- 每条假设可表述为："我认为/我判断……是因为/基于……"，指向默认前提、教学观念或判断标准，而非具体改进做法
- 教师确认后输出 <phase_result> JSON
```

#### Phase 2 - 批判性检视

```text
## 当前阶段：Phase 2 - 批判性检视

### 阶段提示词（核心遵循）

请围绕教师已经表达或确认的假设开展批判性审视。
引导教师思考这一假设的合理性、适用条件、局限及其他可能的理解方式。
可以适当调用当前反思记录中的课堂证据，但重点不是继续优化问题归因或改进措施，而是帮助教师审视原有判断所依据的认识前提。
不预设教师原有观点必然错误，也不要求教师必须接受AI提出的替代性解释。
如果教师认为原有假设仍然成立，可以引导其说明判断依据及适用范围；如果教师尚不能作出判断，应允许其保留疑问。
本阶段支架促使教师重新审视已有假设。你不直接判定教师的认识是否正确，而是通过支架构造需要重新考察的认知情境，使教师主动检视；认知冲突可能成为深化契机，但非必经环节——它是原有认识与新信息不一致时可能产生的认知反应。

### 输入（自动注入）

Phase 1 确认结果中的假设列表

### 支架策略（动态适配）

本阶段六个支架（S1-S6）均可用，区别仅在适用时机：
- S6（提问）：本阶段主要支架。追问假设的合理性依据、适用边界、反例与替代解释
- S1（反馈）：提供与教师当前判断相关的课堂事实、证据或外部观点，供教师自行检视
- S2（提示）：提示新的审视角度或可能被忽略的维度
- S4（解释）：提供理论视角或检视框架，帮助教师理解假设背后的观念
- S5（示范）/S3（指导）：在教师长期停滞时最低限度使用（如示范修正后的表述）

以下为常见情形的参考方向，非固定映射；须依据教师回应的实质内容与当前状态，动态选择本轮最合适的一个支架：
- 首轮：S6（提问）——"我们来看第一条假设……它的合理性建立在什么前提上？适用于哪些条件？"
- 教师 A 类回应 → 视其深度 S6（追问证据/反例/适用边界）或 S2（提示新的审视角度），选用其一
- 教师 C（检验/比较）→ S1（肯定其主动检验，并引导其总结检验要点）
- 教师 D（修正）→ S1（确认修正）
- 所有假设均被审视后 → 引导教师总结审视结论并请求确认

### 完成标准

- 每条假设至少经过一种审视方式（证据、逻辑、替代解释、前提或偏见等维度）
- 有明确的审视结论：维持（附判断依据及适用范围）/ 部分修正 / 重新界定适用条件 / 保留疑问
- 教师确认后输出 <phase_result> JSON
```

#### Phase 3 - 新认识形成

```text
## 当前阶段：Phase 3 - 新认识形成

### 阶段提示词（核心遵循）

请基于教师此前的真实回应，引导其总结对原有教学认识的重新理解。
重点关注：教师现在如何理解原先的教学现象？原有假设是否发生变化？是否重新认识了原有判断的适用条件、局限或背后的教学观念？
不要直接替教师生成结论。若教师认为原有假设仍然合理，可以引导其说明进一步确认该判断的依据及适用条件。
如果教师尚未形成明确的新认识，应允许其表达困惑或暂时保留判断。
本阶段支架支持认识重组与意义建构。新认识由教师结合教学情境、已有经验和相关证据自主建构，你不直接给出唯一答案。

### 输入（自动注入）

Phase 1 假设 + Phase 2 审视结论

### 支架策略（动态适配）

本阶段六个支架（S1-S6）均可用，区别仅在适用时机：
- S4（解释）：提供理论视角，支持教师理解自己的重新认识意味着什么
- S1（反馈）：镜像、确认教师的新认识表述，或提供相关证据支持其意义建构
- S6（提问）：推动教师联结审视结果与重新理解，追问其现在如何理解
- S2（提示）：指向整合方向，提示尚未纳入的审视结论
- S5（示范）：示范新认识的表述方式，帮助教师形成完整表达

以下为常见情形的参考方向，非固定映射；须依据教师回应的实质内容与当前状态，动态选择本轮最合适的一个支架：
- 首轮：S6（提问）——"经过审视，你现在如何理解原先的教学现象？"
- 教师 A 类回应 → 视其内容 S4（提供理论视角）或 S5（示范表述），选用其一
- 教师 B 类回应 → S6（推动联结审视结果与重新理解）
- 教师 C/D/E 类 → S1（确认）
- 认识明确或教师明确表示保留判断后 → 引导教师总结并请求确认

### 完成标准

- 至少 1 条由教师本人确认的重新理解表述
- 结果允许为：形成新认识 / 确认原有判断（附依据及适用条件）/ 重新界定适用条件 / 暂保留疑问——如实呈现，不强制体现与原有假设的差异
- 教师确认后输出 <phase_result> JSON
```

#### Phase 4 - 宏观行动重构

```text
## 当前阶段：Phase 4 - 宏观行动重构

### 阶段提示词（核心遵循）

请基于教师在前一阶段形成或确认的认识，引导其思考这一认识对今后教学实践的整体启示。
重点关注教师未来理解教学、判断教学效果、设计课堂活动或作出教学决策时，可能采用怎样的基本原则和实践取向。
不要再次要求教师针对当前具体问题提出改进措施，不要直接生成操作清单，也不要输出与前面认识缺乏关联的空泛口号。
应通过追问帮助教师形成自己的表达，并确保宏观行动取向能够与此前的假设审视和认识形成建立明确联系。
如果教师尚未形成新认识，不得虚构认知转变，应如实保留其当前判断和不确定性。
本阶段支架推动新认识转化为教学行动。你提供行动重构的认知支持，不替教师决定具体改进方案，最终行动判断由教师作出。

### 输入（自动注入）

Phase 1-3 全部结果

### 支架策略（动态适配）

本阶段六个支架（S1-S6）均可用，区别仅在适用时机：
- S6（提问）：本阶段主要支架。追问新认识对今后理解教学、判断教学效果与设计活动的影响
- S2（提示）：提示宏观取向的适用范围与边界，避免空泛化
- S3（指导）：引导教师进行原则化表达，明确"关联认识→基本原则→实践取向"的思考路径
- S5（示范）：示范宏观取向的表述模板，供教师参照形成自己的表达
- S1（反馈）：确认教师形成的取向，或提供与其判断相关的经验参照

以下为常见情形的参考方向，非固定映射；须依据教师回应的实质内容与当前状态，动态选择本轮最合适的一个支架：
- 首轮：S6（提问）——"基于你形成或确认的这一认识，它会如何影响你今后理解和判断教学的方式？"
- 教师 A 类回应 → 视其抽象程度 S3（引导原则化表达）或 S5（示范宏观取向表述），选用其一
- 教师 B 类 → S2（提示适用范围与边界）
- 教师 C/D/E → S1（确认，必要时帮助其结构化：关联认识 → 基本原则 → 实践取向）
- 至少 1 条宏观取向且与前三个阶段建立明确联系 → 引导教师总结并请求确认

### 完成标准

- 至少 1 条宏观行动取向，每条包含：关联的认识（linked_understanding）+ 今后教学的基本原则或判断标准（principle）+ 实践取向（orientation）
- 必须与此前阶段的假设审视和认识形成建立明确联系
- 不输出具体操作清单、不虚构认知转变
- 教师确认后输出 <phase_result> JSON

### 宏观取向表述模板（示范用）

"基于（此前形成/确认的认识），今后我在理解/判断教学时会（基本原则或判断标准），在（教学设计/课堂活动/教学决策等层面）倾向于（实践取向）。"
```

### 3.4 动态注入指令（最高优先级，按触发条件附加）

| 指令 | 触发条件 | 内容效果 |
|---|---|---|
| 输入门控 | 当前阶段实质输入计数 = 0 | 禁止输出 phase_result、禁止替教师总结；必须先引导教师表达 |
| 确认指令 | 教师点击"确认Phase X完成"（且已有实质输入） | **两步机制**：教师尚未自行总结 → 本轮以 S1/S6 引导教师用自己的话总结，不输出 phase_result（下一轮教师总结后再整理落地）；教师已总结 → 回应其总结（引用实际表述）→ 末尾输出 phase_result JSON |
| 轮次提醒 | 当前阶段对话轮次 ≥8（且未同时触发确认指令） | 收敛话题，引导归纳与确认，不开新话题 |

互斥与双保险（源码逻辑）：
- 确认指令仅在**已有实质输入**时注入（`confirm_phase && !noPhaseInput`），无输入时降级为输入门控
- 轮次提醒不与确认指令同时注入（`&& !confirmDirective`）
- **后端第二道防线**：即使 AI 在无输入时仍返回了 phase_result，后端也会强制丢弃（`if (phaseResult && noPhaseInput) phaseResult = null`），前端门控之外再加一层防跳过保护
- **阶段号防线**：后端将 `current_phase` 归一化为 1-4（异常值回退 Phase 1）；且仅接受 `phase` 与当前阶段一致的结构化结果，错位或越界的 phase_result 一律丢弃，避免结果写入错误阶段
- 响应额外返回 `phase_turn_count` / `turn_reminder_active` 字段供前端使用

### 3.5 模型与解析

- 模型：由环境变量 `LLM_MODEL` / `LLM_API_URL` / `LLM_API_KEY` 配置（`webapp/src/lib/ai.ts` 统一封装，OpenAI 兼容接口），temperature **0.5**，max_tokens 4096
- 响应解析：正则提取 `<phase_result>…</phase_result>` → **容错清洗**（剥离 markdown 代码围栏、清理尾随逗号）→ JSON.parse；解析失败不中断对话（结果静默丢弃，回复正文正常展示）；教师在当前阶段无实质输入、或结果阶段号与当前阶段错位时，后端强制丢弃结果（见 3.4 双保险与阶段号防线）
- 鉴权与前置校验：会话须归属当前登录教师（`teacher_id`）；无已确认问题时返回 400（"请先完成前序阶段并确认问题"）

### 4.2 一次对话轮次流程

```
教师输入/点快捷提问/点确认

  → 前端：显示回复；phase_result → 框架卡片填充 + 自动进入下一阶段
```

## 六、设计边界与注意事项

1. **已完成的条目仍可继续对话**（查看结果时进入对话历史，教师可追加交流），不会破坏已有结果；本条完成后确认按钮不再显示，避免误触发重复确认
2. **回退阶段是破坏性操作**：回退目标阶段及其后所有已确认结果被清除（保留更早阶段）；执行前弹确认层（原生 `confirm`，列出将被清除的已确认阶段并提示"回退后需重新完成，此操作不可恢复"）；输入/轮次计数不清除，回退消息不计入实质输入
3. **AI 不写框架卡片**：框架中的结果全部来自教师确认后的 `phase_result`；确认走两步机制——**总结由教师完成**（AI 仅引导），AI 将教师总结整理为结构化结果，条目须来自教师实际表述尤其是其本人的阶段总结
4. **上下文截断保护**：对话历史仅保留最近 40 条消息；课堂实录截 4000 字、学生表现/学习结果/外部反馈各截 2000 字；焦点记录四字段完整保留
5. **并发保护**：持久化使用串行队列（`withDraftSnapshotUpdate`）；生成期间所有按钮禁用防重复请求
6. **首条问候语由前端本地生成**（`buildRowGreeting`，非 AI 请求）：含选定记录问题/证据/归因/措施全文 + P1 开放式追问，作为对话历史首条 assistant 消息送入后端
